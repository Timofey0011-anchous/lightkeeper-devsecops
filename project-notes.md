# Проектные заметки

## Задача и пользователь

Владелец нескольких фонарей хранит характеристики в одном месте и видит,
какое оборудование требует обслуживания. В минимальной версии один пользователь.

## Функции минимальной версии

1. Добавить фонарь: название, модель, тип питания, состояние.
2. Добавить аккумулятор: модель, типоразмер, ёмкость по маркировке, состояние.
3. Получить список оборудования и отфильтровать его по типу или состоянию.
4. Изменить карточку оборудования.
5. Создать запись обслуживания: дата, операция, заметка.
6. Удалить карточку вместе с её записями обслуживания.

## Модель данных

| Сущность | Поля | Связи |
| --- | --- | --- |
| Equipment | id (UUID), kind, name, model, powerType, capacityMah, status | Одна карточка — много записей обслуживания |
| Maintenance | id (UUID), equipmentId, performedOn, operation, note | Принадлежит одной карточке |

`kind`: `flashlight` или `battery`. `capacityMah` — положительное целое число
для аккумулятора и `null` для фонаря. `powerType` — свободная непустая строка
(например, `18650`, `AA` или `built-in`).
`status`: `ready`, `needs_service`, `retired`.

## Правила

- `id` генерирует сервер; для каждой сущности он уникален.
- `name`: 1–100 символов после удаления пробелов по краям.
- `model`: 1–100 символов; `powerType`: 1–50 символов.
- `operation`: 1–100 символов; `note`: не более 1000 символов.
- Дата обслуживания хранится в формате ISO 8601 `YYYY-MM-DD`.
- Запись обслуживания нельзя создать для несуществующего оборудования.
- Удаление карточки удаляет связанные записи обслуживания в одной транзакции.
- Состояние `ready` — учётная отметка пользователя, а не результат диагностики.

На этом этапе нет регистрации, платежей, удалённого управления фонарём
и аппаратного измерения заряда.
