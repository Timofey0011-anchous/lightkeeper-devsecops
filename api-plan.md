# План REST API

Это спецификация будущего приложения; HTTP-сервер пока не реализован.
Базовый путь: `/api/v1`. Формат запросов и ответов: JSON, UTF-8.
Модель данных и ограничения: [project-notes.md](project-notes.md).

## Операции

| Метод | Путь | Назначение | Успех |
| --- | --- | --- | --- |
| GET | `/health` | Проверка работоспособности приложения | 200 |
| GET | `/api/v1/equipment` | Список оборудования | 200 |
| GET | `/api/v1/equipment/{id}` | Получить карточку | 200 |
| POST | `/api/v1/equipment` | Создать карточку | 201 |
| PATCH | `/api/v1/equipment/{id}` | Изменить переданные поля | 200 |
| DELETE | `/api/v1/equipment/{id}` | Удалить карточку и историю обслуживания | 204 |
| GET | `/api/v1/equipment/{id}/maintenance` | История обслуживания | 200 |
| POST | `/api/v1/equipment/{id}/maintenance` | Добавить запись обслуживания | 201 |

У списка есть необязательные фильтры `kind` и `status`,
а также `limit` (1–100, по умолчанию 20) и `offset` (от 0, по умолчанию 0).
Порядок — по `id` по возрастанию. Ответ списка:
`{"items": [], "total": 0, "limit": 20, "offset": 0}`.
`total` учитывает фильтры, но не пагинацию. Пустой список — 200, а не 404.

## Создание карточки

Запрос `POST /api/v1/equipment`:

```json
{
  "kind": "battery",
  "name": "Запасной аккумулятор",
  "model": "Cell-01",
  "powerType": "18650",
  "capacityMah": 3000,
  "status": "needs_service"
}
```

Ответ 201 возвращает ту же карточку с созданным UUID в поле `id`.
Заголовок `Location` содержит путь `/api/v1/equipment/{id}`.
Для фонаря `capacityMah` передаётся как `null`.
Все показанные поля обязательны при создании; PATCH меняет только переданные,
но итоговая карточка должна удовлетворять тем же ограничениям.
`id` и `kind` через PATCH менять нельзя. Пустой PATCH — ошибка 400.

## Обслуживание

Запрос `POST /api/v1/equipment/{id}/maintenance`:

```json
{
  "performedOn": "2026-11-07",
  "operation": "Внешний осмотр",
  "note": "Обновлена учётная запись оборудования"
}
```

Ответ 201: объект с полями `id`, `equipmentId`, `performedOn`, `operation`, `note`;
путь в `Location`: `/api/v1/equipment/{id}/maintenance/{maintenanceId}`.
GET истории возвращает `{"items": []}` с сортировкой по `performedOn`, затем `id`.
`performedOn` и `operation` обязательны; отсутствующая `note` сохраняется как `""`.
Проверка `/health` возвращает `{"status": "ok"}` с HTTP 200 при работающем приложении.

## Ошибки

| Код | Когда возвращается |
| --- | --- |
| 400 | Невалидный JSON, UUID, дата, поле или параметр фильтра/пагинации |
| 404 | Корректный UUID не соответствует существующей карточке |
| 500 | Внутренняя ошибка; технические подробности не выдаются клиенту |

Неизвестные поля тела запроса отклоняются с 400. Для PATCH проверяется
целостность результата после применения изменений. DELETE отсутствующей
карточки возвращает 404; успешный DELETE — 204 без тела ответа.

```json
{
  "error": "validation_error",
  "message": "Ошибка проверки данных",
  "details": {"name": "Название обязательно"}
}
```

Для 404: `error = "not_found"`; для 500: `error = "internal_error"`.
Поле `details` для этих ошибок — пустой объект. Тексты сообщений могут меняться;
клиент опирается на HTTP-код и `error`.
