# Конфликт и его разрешение

## Где возник конфликт

Файл: `README.md`, строка с назначением проекта (строка 3).
Две ветки созданы от общего предка `2cf2c2f`:

- `docs/usage`: «Назначение: учёт фонарей и их обслуживания.»
- `docs/description`: «Назначение: учёт аккумуляторов и их обслуживания.»

Ветка `docs/usage` была влита в `main` через `--no-ff`.
Затем команда `git merge --no-ff docs/description` действительно остановилась
с конфликтом в `README.md`: Git не мог выбрать один вариант общей строки.

Родитель main перед конфликтом: `b59fab46254e34fd8dfc5e7c788338dfa4e0c812`.
Вливаемый коммит: `7831d3dfa48d6d18172c87e933d058ee72f93184`.

## Что было в конфликтном участке

```text
<<<<<<< HEAD
Назначение: учёт фонарей и их обслуживания.
=======
Назначение: учёт аккумуляторов и их обслуживания.
>>>>>>> docs/description
```

## Как исправлено

Конфликтный участок отредактирован: объединены оба смысла,
удалены маркеры `<<<<<<<`, `=======`, `>>>>>>>`.
Итоговая строка:

> Назначение: учёт фонарей, аккумуляторов и их обслуживания.

Инструкция по проекту из `docs/usage` и словарь из `docs/description` сохранены.
После правки выполнены `git add README.md git-conflict.md docs/evidence/conflict-before.txt`
и отдельный `git commit` с сообщением
`fix: разрешить конфликт назначения проекта в README`.
Это merge-коммит с двумя родителями, потому что он завершает начатое слияние.

## Как проверить

```bash
git log --all --merges --format="%h %p %s"
git show --remerge-diff --format=fuller ':/fix: разрешить конфликт'
git log --graph --oneline --all --decorate
```

Исходный вывод команды, состояние `UU README.md`, три стадии индекса
и файл с маркерами сохранены в `docs/evidence/conflict-before.txt`.
`--remerge-diff` в современных версиях Git восстанавливает конфликт
из родителей и показывает, как merge-коммит его разрешил.
